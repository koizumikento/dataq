# dataq v0.1.19 Release Notes

Released: 2026-07-14

## User-visible changes

- `aggregate sum` now preserves integral results throughout the JSON `i64` / `u64` range, and metric sorting compares integers exactly even above `2^53` or when integer and floating-point values are mixed. Syntactically integral sums outside the supported JSON integer range return exit `3` instead of being silently rounded. ([PR #20](https://github.com/koizumikento/dataq/pull/20))
- Native `profile` keeps representable `min`, `max`, `mean`, `p50`, and `p95` values finite for very large finite JSON numbers, avoiding overflow in intermediate rounding and averaging. ([PR #21](https://github.com/koizumikento/dataq/pull/21))
- qsv 20.1 stats CSV normalization now distinguishes dataset row counts, type counts, and finite numeric sample counts across string columns, `NULL` columns, empty datasets, and Float columns containing `NaN`. ([PR #23](https://github.com/koizumikento/dataq/pull/23))
- A downstream process closing stdout now produces a clean consumer-closed exit `0` instead of a Rust `BrokenPipe` panic. Requested `--emit-pipeline` diagnostics remain on stderr, while other stdout write or flush failures return exit `1`. ([PR #22](https://github.com/koizumikento/dataq/pull/22))
- The bundled `dataq` and rules/recipes agent skills are synchronized with the current CLI, MCP tools, contracts, doctor profiles, emit-plan behavior, pipeline diagnostics, and native rule/recipe responsibilities. ([PR #14](https://github.com/koizumikento/dataq/pull/14), [PR #17](https://github.com/koizumikento/dataq/pull/17))

## Bug fixes and contract hardening

- The shared CSV reader rejects exact, case-sensitive duplicate headers before converting any row. CLI failures include the duplicate name and zero-based column indexes, return `input_usage_error` / exit `3`, and emit no partial output. ([PR #19](https://github.com/koizumikento/dataq/pull/19))
- qsv normalization no longer reverses rounded `sparsity` into row counts. It accepts only explicit record counts, complete Integer signed counters, or provably empty metadata as exact dataset evidence, and rejects missing, conflicting, or out-of-range counters. ([PR #23](https://github.com/koizumikento/dataq/pull/23))
- `$feat-add` now formalizes feature-level branch/worktree/PR isolation, explorer/worker/parent ownership, full quality gates, and post-rebase validation. `$rev-pass` now reviews one immutable committed diff with a machine-readable verdict. ([PR #15](https://github.com/koizumikento/dataq/pull/15), [PR #16](https://github.com/koizumikento/dataq/pull/16))
- Deterministic tests now detect structural drift across skill metadata, invocation rules, distributed mirrors, and positive/near-miss routing cases. These tests validate structure and packaging boundaries rather than runtime model selection. ([PR #18](https://github.com/koizumikento/dataq/pull/18))
- Release automation now checks out the tagged source before reading `docs/releases/<tag>.md`, ensuring GitHub Releases receive the committed notes body. Release verification also isolates recipe-lock tool probes from runner-installed `jq`, `yq`, and `mlr`, so tagged builds do not depend on host tool availability. ([PR #24](https://github.com/koizumikento/dataq/pull/24), [PR #25](https://github.com/koizumikento/dataq/pull/25))

## Breaking changes / migration

- No commands, options, or existing output fields were intentionally removed.
- Duplicate CSV headers are no longer accepted; rename or deduplicate headers before processing.
- Integral aggregate sums outside the JSON `i64` / `u64` range now return exit `3`; adjust units or representation before aggregation when such values are possible.
- qsv stats normalization requires a nonblank `nullcount` / `null_count` for each row and an exact dataset count source. Add an explicit `record_count`-family column when an all-string or otherwise ambiguous stats output cannot prove its row count.
- Pipelines that intentionally close stdout early now receive exit `0`, including when the underlying command result would otherwise be exit `2`. Non-`BrokenPipe` stdout write and flush failures now return exit `1`.
