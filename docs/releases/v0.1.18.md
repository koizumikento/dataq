# dataq v0.1.18 Release Notes

Released: 2026-06-08

## User-visible changes

- `transform sql` now preserves DuckDB result row order while still canonicalizing each returned row. This keeps explicit SQL `ORDER BY` output stable for downstream agents and scripts. ([PR #8](https://github.com/koizumikento/dataq/pull/8))
- `contract` coverage now includes additional public commands including `join`, `aggregate`, `recipe-replay`, `schema-infer`, `ingest-tabular`, `ingest-jc`, and `emit-plan`. ([PR #9](https://github.com/koizumikento/dataq/pull/9))
- `profile` supports repeatable `--field <name-or-path>` projection, `--allow-missing-fields`, `returned_field_count`, and `missing_fields`. MCP `dataq.profile` exposes the same projection controls. ([PR #10](https://github.com/koizumikento/dataq/pull/10))
- `profile --brief` adds compact LLM-oriented output with `--max-fields` and `--sort-fields`, plus MCP parity. ([PR #11](https://github.com/koizumikento/dataq/pull/11))
- `aggregate` supports deterministic top-k workflows with `--sort-by`, `--order`, and `--limit`, plus MCP parity. ([PR #12](https://github.com/koizumikento/dataq/pull/12))
- README, command spec, and the bundled `dataq` skill now include an LLM / agent quickstart using `doctor`, `contract`, `emit plan`, `profile --brief`, `aggregate`, `transform sql`, and `--emit-pipeline`. ([PR #13](https://github.com/koizumikento/dataq/pull/13))

## Bug fixes and contract hardening

- Added regression coverage for transform SQL ordering, expanded contract command coverage, profile projection/brief determinism, aggregate top-k ordering, MCP argument schemas, and release-facing docs.

## Breaking changes

- None.
